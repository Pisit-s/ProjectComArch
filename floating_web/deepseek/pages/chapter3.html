บทที่ 3: IEEE 754 Single Precision

Learning Objectives

  • อธิบายเหตุผลที่คอมพิวเตอร์ใช้ Floating-Point แทนจำนวนจริง
  • เข้าใจ Normalized Binary Scientific Notation รูปแบบ 1.xxxxx × 2^e
  • ระบุส่วน Sign, Exponent และ Fraction ของ Single Precision (32 บิต) ได้
  • Encode เลขฐานสิบเป็น IEEE 754 และ Decode กลับได้ พร้อมเข้าใจข้อจำกัดของความแม่นยำ

แนวคิดหลัก

ในฐานสิบ เราเขียนเลขวิทยาศาสตร์ได้ เช่น 1.25 × 10³ ในฐานสองเราก็เขียนได้เช่นกัน เช่น 1.011 × 2² (ซึ่งเท่ากับ 101.1₂ = 5.5₁₀)

โครงสร้าง Single Precision 32 บิต

Sign1 บิต (b31)
Exponent8 บิต (b30–b23)
Fraction23 บิต (b22–b0)
  • Sign — 0 = บวก, 1 = ลบ
  • Exponent — เก็บ e + 127 (Bias = 127) เรียกว่า Biased Exponent
  • Fraction — เศษ 23 บิตของ Significand สำหรับเลข Normalized ซึ่งมี Hidden Leading 1 (Significand = 1.Fraction)

ขั้นตอน Encoding

  1. ตรวจเครื่องหมายและหาค่า Absolute Value
  2. แปลงค่าเป็นเลขฐานสอง
  3. Normalize ให้อยู่ในรูป 1.xxxxx × 2^e
  4. กำหนด Sign Bit
  5. คำนวณ Biased Exponent = e + 127
  6. สร้าง Fraction field 23 บิตและทำ Rounding
  7. รวมเป็น 32 บิต

ตัวอย่าง: 5.75₁₀

5.75₁₀ = 101.11₂ = 1.0111 × 2²
Sign     = 0 (บวก)
e        = 2 → Biased = 2 + 127 = 129 = 10000001₂
Fraction = 0111000…0 (23 บิต)
รวม 32 บิต = 0 10000001 01110000000000000000000
Hex = 0x40B80000

ขอบเขตของเครื่องมือ

เวอร์ชันนี้รองรับค่า Normalized Finite เท่านั้น ยังไม่รองรับ Subnormal, Infinity, NaN และ Signed Zero — หากป้อนค่าที่อยู่นอกขอบเขต เครื่องมือจะแจ้งเตือน

Interactive: IEEE 754 Encoder / Decoder

ลอง: 5.75 → 0x40B80000 · -13.25 → 0xC1540000

ต้องมี 32 บิต (เฉพาะ 0/1) — ช่องว่างจะถูกตัดออกก่อนตรวจสอบ

สรุปท้ายบท

  • IEEE 754 Single Precision ใช้ 32 บิต: Sign 1 + Exponent 8 + Fraction 23
  • Bias = 127, Exponent ที่เก็บคือ e + 127
  • เลข Normalized มี Hidden Leading 1: Significand = 1.Fraction
  • ค่าฐานสิบบางค่า (เช่น 0.1) ไม่สามารถแทนได้แม่นยำด้วย 32 บิต ค่าที่จัดเก็บจึงต่างจากค่าที่ป้อน
