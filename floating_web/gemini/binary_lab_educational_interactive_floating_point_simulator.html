CHAPTER 01

ระบบเลขฐานและจำนวนเต็มฐานสอง (Binary Integers)

วัตถุประสงค์การเรียนรู้

  • เข้าใจแนวคิดของระบบเลขฐานสิบ (Base-10) และเลขฐานสอง (Base-2)
  • คำนวณค่าน้ำหนักประจำหลัก (Positional Weights: 2⁰, 2¹, 2², ...)
  • แปลงจำนวนเต็มฐานสองแบบไม่มีเครื่องหมาย (Unsigned 8-bit Integer) เป็นเลขฐานสิบได้ถูกต้อง

1. ค่าประจำหลักของเลขฐานสิบ vs ฐานสอง

มนุษย์คุ้นเคยกับ **ระบบเลขฐานสิบ (Base-10)** ซึ่งมีตัวเลข 0–9 และค่าประจำหลักจะเพิ่มขึ้นเป็นเท่าของ 10 ได้แก่ $10^0 = 1$, $10^1 = 10$, $10^2 = 100$ เป็นต้น แต่คอมพิวเตอร์สร้างขึ้นจากวงจรอิเล็กทรอนิกส์ที่มีสถานะสวิตช์เพียง 2 สถานะ คือ **ปิด (0)** และ **เปิด (1)** จึงต้องใช้ **ระบบเลขฐานสอง (Base-2)**

// เปรียบเทียบค่าประจำหลัก 8 บิต (Unsigned 8-bit Integer)
b7 (2⁷) = 128
b6 (2⁶) = 64
b5 (2⁵) = 32
b4 (2⁴) = 16
b3 (2³) = 8
b2 (2²) = 4
b1 (2¹) = 2
b0 (2⁰) = 1

สูตรการหาค่าเลขฐานสิบจากบิตฐานสอง: $$\text{Decimal Value} = \sum_{i=0}^{7} (b_i \times 2^i)$$ ช่วงค่าของ Unsigned 8-bit Integer จะเริ่มจาก 00000000₂ (0) ถึง 11111111₂ (255)

📌 สรุปท้ายบทที่ 1

เลขฐานสองใช้ฐานเป็น 2 แต่ละหลักคือ $2^i$ บิตที่เป็น 1 จะนำค่าน้ำหนักนั้นมารวมกัน ส่วนบิตที่เป็น 0 จะไม่นำมารวม ในขนาด 8 บิต แบบไม่มีเครื่องหมาย จะแทนค่าได้สูงสุด $2^8 - 1 = 255$

CHAPTER 02

เศษส่วนฐานสิบและเศษส่วนฐานสอง (Binary Fractions)

วัตถุประสงค์การเรียนรู้

  • เข้าใจค่าน้ำหนักยกกำลังติดลบ ($2^{-1}, 2^{-2}, 2^{-3}, \dots$) ของเศษส่วนฐานสอง
  • แปลงเศษส่วนฐานสิบเป็นฐานสองด้วยอัลกอริทึม "คูณเศษส่วนด้วย 2 ซ้ำๆ"
  • เข้าใจว่าทำไมเลขทศนิยมบางค่า เช่น $0.1_{10}$ ไม่สามารถเก็บได้ตรงเป๊ะในคอมพิวเตอร์ (Repeating Fraction)

1. น้ำหนักหลักเศษส่วนฐานสอง (Fractional Weights)

เช่นเดียวกับเลขฐานสิบหลังจุดทศนิยมที่มีค่าประจำหลักเป็น $10^{-1} = 0.1$, $10^{-2} = 0.01$ หลังจุดทศนิยมฐานสองจะมีค่าน้ำหนักเป็น:

b₁ (2⁻¹) = 0.5
b₂ (2⁻²) = 0.25
b₃ (2⁻³) = 0.125
b₄ (2⁻⁴) = 0.0625

2. การแปลงเศษส่วนฐานสิบเป็นฐานสอง (Multiply by 2 Method)

วิธีการแปลงคือ: นำเศษส่วนไป **คูณด้วย 2** ดึงส่วนจำนวนเต็ม (0 หรือ 1) ออกมาเป็นบิตคำตอบ แล้วนำเศษส่วนที่เหลือไปคูณ 2 ต่อ ทำเช่นนี้จนกว่าเศษส่วนจะเป็น 0 หรือครบจำนวนบิตที่ต้องการ

คลิกที่แต่ละบิตเศษส่วนเพื่อดูการคำนวณค่าทศนิยมฐานสิบ

ป้อนเศษส่วนฐานสิบ (เช่น 0.375 หรือ 0.1) เพื่อดูขั้นตอนการแปลงทีละบรรทัด

📌 สรุปท้ายบทที่ 2

เศษส่วนฐานสิบจำนวนมาก เช่น $0.1_{10}$ หรือ $0.2_{10}$ ไม่สามารถแปลงเป็นเศษส่วนฐานสองที่มีจำนวนบิตจำกัดได้ลงตัว (กลายเป็น **เศษส่วนซ้ำแบบไม่สิ้นสุด**) การเก็บข้อมูลในคอมพิวเตอร์จึงต้องตัดจบ (Truncate/Round) ทำให้เกิด **ค่าความคลาดเคลื่อน (Absolute Error)** เสมอ

CHAPTER 03

การแทนค่า Floating-Point ตามมาตรฐาน IEEE 754

วัตถุประสงค์การเรียนรู้

  • เข้าใจโครงสร้าง IEEE 754 Single Precision 32 บิต (Sign 1 บิต, Exponent 8 บิต, Fraction 23 บิต)
  • เข้าใจหน้าที่ของ **Exponent Bias = 127** และ **Hidden Leading Bit (1.xxxx)**
  • สามารถทำการ Encode จากทศนิยมฐานสิบเป็นบิต Float32 และ Decode กลับเป็นค่าตัวเลขได้

1. โครงสร้าง IEEE 754 Single Precision (32-bit Layout)

มาตรฐาน IEEE 754 แบ่งบิต 32 บิตออกเป็น 3 ส่วนหลัก ดังนี้:

S
Exponent (8 bits)
Fraction / Mantissa (23 bits)
1. Sign Bit (1 บิต):

0 = ค่าบวก, 1 = ค่าลบ

2. Exponent (8 บิต):

ใช้ Exponent Bias = 127
$$\text{Stored Exp} = e + 127$$

3. Fraction (23 บิต):

เก็บส่วนหลังจุดของเลข Normalized
$$\text{Significand} = 1.F$$

สูตรการคำนวณ Decoding ค่า IEEE 754 (Normalized Value):

$$\text{Value} = (-1)^{\text{Sign}} \times (1 + \text{Fraction}) \times 2^{(\text{Exponent} - 127)}$$
Bit String Representation (32 bits): Hex: 0x40B80000

⚠️ ขอบเขตของเครื่องมือ:

เวอร์ชันนี้ออกแบบมาสำหรับการแทนค่าเลขปกติ (Normalized Numbers) เป็นหลัก ค่าพิเศษเช่น Subnormal, Infinity (±∞), NaN และ Signed Zero มีการจัดการตามมาตรฐาน Float32 เบื้องต้น

📌 สรุปท้ายบทที่ 3

IEEE 754 Single Precision ใช้ 32 บิตแทนจำนวนจริง โดยแยกเป็น Sign (1), Exponent (8, Bias 127), และ Fraction (23) โดยใช้หลักการ **Hidden Bit 1** สำหรับเลข Normalized ทำให้ประหยัดพื้นที่จัดเก็บได้ 1 บิต

CHAPTER 04

การบวกและการลบ Floating-Point (Float32 Arithmetic)

วัตถุประสงค์การเรียนรู้

  • เข้าใจกระบวนการ 7 ขั้นตอนของการบวกลบ Float32 ใน ALU/FPU ของคอมพิวเตอร์
  • เข้าใจขั้นตอนการปรับ Exponent ให้เท่ากัน (Exponent Alignment) และการเลื่อน Significand
  • อธิบายได้ว่าทำไม $0.1 + 0.2 \neq 0.3$ ในการคำนวณแบบ Float32

ขั้นตอนหลัก 7 ขั้นตอนของ FPU (Floating-Point Arithmetic)

1.
Convert Operands: แปลงค่า A และ B เป็น Float32 ก่อนคำนวณ
2.
Unpack Fields: แยก Sign, Exponent, Significand (1.F)
3.
Align Exponents: เลื่อน Significand ของตัวที่มี Exponent น้อยกว่าไปทางขวา
4.
Add/Subtract: บวกหรือลบ Significand ตามเครื่องหมาย
5.
Normalize Result: เลื่อน Significand ผลลัพธ์ให้อยู่ในรูป 1.xxxxx
6.
Rounding: ปัดเศษให้พอดีความแม่นยำ 23 บิต

การบวกลบ Float32 ต้องปรับ Exponent ให้เท่ากันเสมอ ซึ่งอาจทำให้เกิด **Significand Shift (Right Shift)** ส่งผลให้บิตนัยสำคัญระดับล่างหลุดและสูญหายไป นอกจากนี้ เมื่อ operands ถูกแปลงเป็น Float32 ก่อนคำนวณ ผลลัพธ์ที่ได้จึงเป็นไปตามกฎความแม่นยำของ FPU เช่น $0.1 + 0.2 = 0.30000001192092896$
