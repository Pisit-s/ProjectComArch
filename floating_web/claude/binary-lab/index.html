บทที่ 1: ระบบเลขฐานและจำนวนเต็มฐานสอง

Learning Objectives
  • เข้าใจค่าประจำหลัก (Place Value) ของระบบเลขฐาน
  • อธิบายความสัมพันธ์ระหว่างเลขฐานสิบ (Base 10) และเลขฐานสอง (Base 2)
  • แปลงจำนวนเต็มฐานสองแบบไม่มีเครื่องหมาย (Unsigned) เป็นฐานสิบได้
  • บอกได้ว่าแต่ละบิตมีส่วนต่อค่ารวมอย่างไร

1.1 ระบบเลขฐานสิบและค่าประจำหลัก

เลขฐานสิบใช้ตัวเลข 0–9 และแต่ละหลักมี ค่าประจำหลัก เป็นกำลังของ 10 เช่น 10⁰ (หลักหน่วย), 10¹ (หลักสิบ), 10² (หลักร้อย)

345 = 3×10² + 4×10¹ + 5×10⁰ = 300 + 40 + 5

1.2 ระบบเลขฐานสอง

เลขฐานสองใช้เพียง 0 และ 1 แต่ละตำแหน่งเรียกว่า บิต (bit) มีน้ำหนักเป็นกำลังของ 2: 2⁰=1, 2¹=2, 2²=4, 2³=8, …, 2⁷=128

วิธีแปลงเป็นฐานสิบ: คูณบิตแต่ละตำแหน่งด้วยน้ำหนัก แล้วรวมผล บิตที่เป็น 0 ไม่เพิ่มค่า ส่วนบิตที่เป็น 1 เพิ่มค่าเท่ากับน้ำหนักของตำแหน่งนั้น

ตัวอย่าง 00001010₂ = 0×128 + 0×64 + 0×32 + 0×16 + 1×8 + 0×4 + 1×2 + 0×1 = 8 + 2 = 10₁₀

1.3 Unsigned 8-bit Integer

จำนวนเต็มไม่มีเครื่องหมายขนาด 8 บิตเก็บได้ 2⁸ = 256 ค่า คือ 0 ถึง 255 (00000000₂ ถึง 11111111₂ โดย 255 = 128+64+32+16+8+4+2+1)

Interactive: 8-bit Binary Integer Explorer

คลิกที่บิตเพื่อสลับ 0/1 แล้วดูว่าแต่ละบิตเพิ่มค่าเท่าไร

Summary / สรุปท้ายบท
  • ค่าประจำหลักของฐานสิบคือกำลังของ 10 และของฐานสองคือกำลังของ 2
  • ค่าฐานสิบ = ผลรวมของ (บิต × น้ำหนักประจำหลัก) บิต 0 ไม่เพิ่มค่า บิต 1 เพิ่มค่าเท่าน้ำหนัก
  • น้ำหนักของ 8 บิตคือ 128, 64, 32, 16, 8, 4, 2, 1 จึงแทนค่า 0–255 ได้

บทที่ 2: เศษส่วนฐานสิบและเศษส่วนฐานสอง

Learning Objectives
  • เข้าใจค่าประจำหลักของเศษส่วนทั้งฐานสิบและฐานสอง
  • คำนวณค่าฐานสิบจากเศษส่วนฐานสองได้
  • แปลงเศษส่วนฐานสิบเป็นฐานสองด้วยการคูณ 2 ซ้ำ ๆ
  • เข้าใจว่าเศษส่วนบางค่าแทนด้วยบิตจำนวนจำกัดไม่ได้พอดี

2.1 ค่าประจำหลักของเศษส่วน

หลังจุดทศนิยม ค่าประจำหลักเป็นกำลังติดลบ: ฐานสิบคือ 10⁻¹=0.1, 10⁻²=0.01, 10⁻³=0.001 ส่วนฐานสองคือ 2⁻¹=0.5, 2⁻²=0.25, 2⁻³=0.125, … เขียนเศษส่วนฐานสองเป็น 0.b₁b₂b₃…₂

0.101₂ = 1×2⁻¹ + 0×2⁻² + 1×2⁻³ = 0.5 + 0 + 0.125 = 0.625₁₀

Interactive A: 16-bit Binary Fraction Explorer

2.2 แปลงเศษส่วนฐานสิบเป็นฐานสอง

คูณเศษส่วนด้วย 2 ซ้ำ ๆ: ส่วนจำนวนเต็ม ของผลคูณคือบิตถัดไป (b₁, b₂, …) แล้วนำ เศษส่วนที่เหลือ ไปคูณต่อ จนเหลือ 0 หรือครบจำนวนบิตที่ต้องการ

0.375 × 2 = 0.75 → บิต 0, เหลือ 0.75 0.75 × 2 = 1.5 → บิต 1, เหลือ 0.5 0.5 × 2 = 1.0 → บิต 1, เหลือ 0 (จบ) ดังนั้น 0.375₁₀ = 0.011₂

2.3 ทำไม 0.1 จึงแทนไม่ได้พอดี

ค่า 0.1₁₀ = 0.0001100110011…₂ เป็นรูปแบบ ซ้ำไม่สิ้นสุด (เหมือน 1/3 = 0.333… ในฐานสิบ) เมื่อเก็บบิตจำกัด จึงได้ ค่าประมาณ (Approximation) และมี Absolute Error = |ค่าจริง − ค่าประมาณ| เครื่องมือนี้ตัดบิตที่เกินทิ้ง (Truncate) ส่วน Float32 ในบทถัดไปจะปัดเศษ

Interactive B: Decimal Fraction Converter

Summary / สรุปท้ายบท
  • น้ำหนักบิตเศษส่วนคือ 2⁻¹, 2⁻², 2⁻³, … (ครึ่งหนึ่งของบิตก่อนหน้า)
  • แปลงฐานสิบ → ฐานสองด้วยการคูณ 2 ซ้ำ เก็บส่วนจำนวนเต็มเป็นบิต
  • เศษส่วนที่ตัวส่วน (หลังย่อ) มีตัวประกอบอื่นนอกจาก 2 เช่น 0.1 จะซ้ำไม่สิ้นสุดในฐานสอง จึงต้องประมาณและมีความคลาดเคลื่อน

บทที่ 3: IEEE 754 Single Precision

Learning Objectives
  • อธิบายเหตุผลที่ต้องใช้ Floating-Point
  • เชื่อมโยง Scientific Notation ฐานสิบกับรูปแบบฐานสอง 1.xxx × 2ᵉ
  • ระบุ Sign, Exponent, Fraction ของ Float32 ได้
  • Encode ค่าฐานสิบเป็น 32 บิต และ Decode กลับได้

3.1 ทำไมต้อง Floating-Point

จำนวนเต็มและ Fixed-point เก็บได้ในช่วงแคบ แต่เราต้องการเก็บทั้งค่ามหาศาล (เช่น 6.02×10²³) และค่าเล็กจิ๋ว (เช่น 1.6×10⁻¹⁹) ด้วยจำนวนบิตคงที่ Floating-Point จึงเก็บ “เลขนัยสำคัญ” แยกจาก “ตำแหน่งจุดทศนิยม” เหมือน Scientific Notation 1.25 × 10³ ฐานสองใช้รูป Normalized 1.xxxxx × 2ᵉ

3.2 โครงสร้าง 32 บิต

Sign 1 บิต | Exponent 8 บิต | Fraction 23 บิต ค่า = (−1)^Sign × (1 + Fraction/2²³) × 2^(Exponent − 127)
  • Sign: 0 = บวก, 1 = ลบ
  • Exponent: เก็บ e + Bias 127 (Biased Exponent) ทำให้เก็บเลขชี้กำลังติดลบโดยไม่ต้องมีบิตเครื่องหมาย
  • Fraction: เก็บเฉพาะบิตหลัง “1.” เพราะบิต 1 นำหน้าของเลข Normalized เป็น Hidden Leading 1 ไม่ต้องเก็บ

3.3 ขั้นตอน Encode (ตัวอย่าง 5.75)

1) เครื่องหมายบวก, |x| = 5.75 2) ฐานสอง: 5 = 101, 0.75 = 0.11 → 101.11₂ 3) Normalize: 101.11₂ = 1.0111₂ × 2² (e = 2) 4) Sign = 0 5) Biased Exponent = 2 + 127 = 129 = 10000001₂ 6) Fraction = 0111 แล้วเติม 0 ให้ครบ 23 บิต (ถ้ายาวเกินให้ปัดเศษ) 7) 0 10000001 01110000000000000000000 = 0x40B80000

Decode

ย้อนกลับ: แยก 1+8+23 บิต → หา e = Exponent − 127 → Significand = 1 + Fraction/2²³ → คูณ (−1)^Sign × Significand × 2ᵉ

ขอบเขตของเครื่องมือ: รองรับ Single Precision แบบ Normalized (และค่า 0) เท่านั้น ไม่รองรับ Subnormal, Infinity, NaN และ Double Precision — หากป้อนค่าเหล่านี้จะแสดงข้อความแจ้งเตือน เลขทศนิยมส่วนมาก (เช่น 0.1) จัดเก็บได้เพียงค่าประมาณ

Interactive: IEEE 754 Encoder / Decoder

Summary / สรุปท้ายบท
  • Float32 = Sign 1 + Exponent 8 + Fraction 23 บิต; ค่า = (−1)^S × 1.F × 2^(E−127)
  • Bias = 127, Normalization ทำให้มี Hidden 1 จึงได้ความแม่นยำ 24 บิตนัยสำคัญ
  • Encode: ฐานสอง → Normalize → หา Biased Exponent → เก็บ Fraction; Decode ทำย้อนกลับ
  • ความแม่นยำจำกัด จึงต้องปัดเศษ ค่าที่เก็บจริงอาจต่างจากค่าที่ป้อน

บทที่ 4: การบวกและการลบ Floating-Point

Learning Objectives
  • เข้าใจว่าการบวก/ลบ Floating-Point มีหลายขั้นตอนกว่าเลขจำนวนเต็ม
  • ติดตามขั้นตอน: ปรับ Exponent → บวก/ลบ Significand → Normalize → Rounding
  • เข้าใจผลของการปัดเศษและความแม่นยำที่จำกัด

4.1 ขั้นตอนหลัก

  1. แปลง Operand ทั้งสองเป็น Float32 ก่อน (ค่าที่เก็บจริงคือค่าที่ใช้คำนวณ)
  2. แยก Sign, Exponent, Significand (ใส่ Hidden 1 กลับ)
  3. ปรับ Exponent ให้เท่ากัน โดยเลื่อน Significand ของค่าที่ Exponent น้อยกว่าไปทางขวา
  4. บวกหรือลบ Significand ตามเครื่องหมายและ Operation
  5. Normalize ให้อยู่ในรูป 1.xxx
  6. ปัดเศษให้พอดี 23 บิต Fraction (Round to Nearest, Ties to Even)
  7. Encode เป็น Float32
ตัวอย่าง 1.5 + 0.25 1.5 = 1.1₂ × 2⁰, 0.25 = 1.0₂ × 2⁻² เลื่อน 0.25 ขวา 2 บิต → 0.01₂ × 2⁰ 1.10 + 0.01 = 1.11₂ × 2⁰ = 1.75
ขั้นตอนเป็น แบบจำลองเพื่อการเรียนรู้ ใช้ Significand 24 บิต + 3 บิตเสริม (Guard, Round, Sticky) ไม่ใช่รายละเอียดวงจรของ CPU ทุกรุ่น เครื่องมือนี้ไม่รองรับ Overflow/Underflow/ค่าพิเศษ และผลลัพธ์ถูกตรวจเทียบกับ Math.fround ทุกครั้ง

Interactive: Float32 Arithmetic Simulator

ลองกรณีคลาสสิก: 0.1 + 0.2 หรือ 16777216 + 1

Summary / สรุปท้ายบท
  • ต้องปรับ Exponent ให้เท่ากันก่อน โดยเลื่อน Significand ของค่าที่เล็กกว่า
  • จากนั้นบวก/ลบ Significand (ลบ = บวกด้วยค่าที่กลับเครื่องหมาย), Normalize แล้ว Rounding
  • บิตที่หลุดจากการเลื่อนและการปัดเศษทำให้ผลต่างจากค่าทางคณิตศาสตร์ เช่น 0.1+0.2 ≠ 0.3 พอดี
